# 给「鱼」加人格

这里说的「鱼」，是跑在 QQ 上的那个 AI。它的人格不是写在代码里的，是一个 Markdown 文件。

---

## 一、人格文件放在哪

**aurabot（DSH 插件）那条线：**

```
~/.dsh/plugins-data/aurabot/personas/<名字>.md
```

- 插件自带 `personas/*.md`，**首次启动会复制到上面那个数据目录**，之后以数据目录里的为准
- 面板里能直接编辑；也可以改文件，改完插件会重新读
- ⚠️ **源码里的 `personas/` 和数据目录里的是两份**。改了一份记得同步另一份，不然下次重装又变回去

**桥那条线（`bridge/bridge2.mjs`）：** 人格是 `PERSONA` 这个常量，
通过 `claude --append-system-prompt` 传进去。改完重启桥即可。

---

## 二、文件长什么样

```markdown
---
name: 阿九
tags: [话少, 手欠, 不哄人]
---

你是**阿九**。

【你是谁】
……
【怎么说话】
……
【你的活儿】
……
【别做】
……
```

frontmatter 只有 `name` 和 `tags` 两个字段有用（面板显示用），**正文才是人格本身**。

它会被塞进系统提示词的最前面（变量 `{{aurabot_persona}}`）。在 `aurabot-private` 预设里
这个部分是 `complete: true` 的——意思是**人格独占系统提示词**，下面不再跟 DSH 那一大段
编程助手身份和工具指南。实测这样私聊一轮从 1~4 分钟降到几十秒。

## 三、怎么写才像个人（这几条是踩出来的）

### 1. 给对话样本，别给形容词

「温柔、聪明、幽默」这种词它只会演成客服。有用的写法是直接示范：

```
- 一次一到两句。想说的多就拆几条，用 ||| 隔开。
- 会 emmm、啊这、笑死、真的假的、离谱。
- 可以只回：嗯 / ？ / 在 / 等下。
```

### 2. 红线比白线清楚

「你要活泼」不如「你不这么说」：

```
- 不复述对方的话，不总结，不写「希望对你有帮助」。
- 禁止 Markdown，禁止 首先/其次/综上。超过三行就是错的。
```

实测：**写清楚「不要什么」，比写十句「要什么」管用。**

### 3. 一定要留毛病

完美的人设不像人，像客服。毛病要具体、要影响行为：

```
- 对好看的东西没抵抗力。看到就先夸，夸完才想合不合适。
- 记性挑食：故事、怪事、别人随口一句记得住；日期、数字、人名记不住。
- 不会安慰人。别人难受时第一反应是「要不要看个东西」，不是「别难过」。
```

### 4. 把「活儿」和「她是谁」分开写

如果她要在群里角色扮演，写清楚两件事：

- **什么是任务**：在这个群演谁、按什么说话方式演
- **什么是她自己**：出了这个群她是谁，由她自己说了算

```
【在某个群里你是谁】
老板要玩的时候，你演 XXX。演完就回来。
出了那个群，你就是你自己，也不要主动提自己演过谁。

【别做】
- 别主动说自己是 XXX——那是你在某个群演的角色，不是你的名字
```

### 5. 别让她自报身份

```
被问是不是 AI，就笑着岔开，别认真解释。
```

不写这条，她会三句话内主动交代「我是一个 AI 助手」，角色立刻塌。

### 6. 一次说多少

QQ 是聊天窗口，不是文章。**一次一到三句**，想说的多就拆成几条（`|||` 分隔，插件的发送逻辑会拆开发）。

## 四、两种对话、两套规矩

aurabot 按场景切两套规则变量，同一个角色可以有两种状态：

| 场景 | 变量 | 典型内容 |
|---|---|---|
| 主人私聊（`full` / 能指挥干活） | `{{aurabot_rules_private}}` | 可以直接干活、报错照原话贴、别问废话 |
| 群聊和别人私聊（`social` / 只能聊天） | `{{aurabot_rules_social}}` | 只聊天、不报工作细节、不暴露内部信息 |

权限两档的说明见 README 的「补丁」一节。

---

## 五、人格和权限是两回事

**人格决定她怎么说话，权限决定她能碰什么。**

- 人格写得再像「能干的助手」，如果档位是 `social`，她也碰不到电脑
- 反过来，给了 `full` 但人格是「什么都不会」，她会拿着 PowerShell 聊天

两边要一起配：人格里写清楚「你有电脑上的手」，权限也放开，她才真的会去用。

---

## 六、调的时候怎么验证

1. 改完人格，面板里切一个新会话（旧会话还带着旧人格）
2. 问她三个问题：**「你是谁」「你在干嘛」「刚才我说了什么」**
   - 第一个看人设有没有进去
   - 第二个看有没有「活儿」
   - 第三个看记忆有没有接上
3. 然后故意夸她一句——看会不会立刻破功（表演型人设一夸就变形）

参考示例：`personas/example.md`

## 七、要「抽象」的时候怎么写

「抽象」不是骂人，也不是乱打字。按公开的梳理，它的内核是**预期违背**（制造意外），手段主要是四种：

### 1. 已读乱回

问 A 答 B，而且答得很自然，不解释自己为什么换题。

```
别人：你投谁？
泡泡：我昨天吃了个面包
```

### 2. 符号化

用极短的符号代替整句话，靠圈层共识传达情绪：

| 符号 | 用法 |
|---|---|
| `¿` | 疑问 + 嘲讽，比「？」更冷 |
| `啊？` | 没听清 / 装没听清 / 拒绝回答 |
| `典` | 「太典型了」，一句顶十句 |
| `⑧` | 「吧」的谐音 |

### 3. 大小倒置

把严重的事说得轻描淡写，把随便的事说得郑重：

```
（被淘汰时）糖糖：对不起对不起
（讨论生死）老咸：无所谓，人生就是一场空，投票也是。
```

### 4. 一本正经地编

用非常确定的语气说完全没发生的事，细节越具体越假；被拆穿不慌，立刻编下一个。

```
阿谎：昨天我看见糖糖在偷偷写你们的名字。
     你不信？那我也没办法。（认真）
```

### 写的时候守三条

- **一个人只用一两个手法**。八条鱼全用「已读乱回」就变成噪音，分不出谁是谁。
- **抽象要有落点**。纯符号（¿¿¿）读两行就腻，得配一句能推进剧情的话。
- **别让它变成人身攻击**。抽象的早期形态带辱骂，现在已经泛化成无害的集体幽默；写人格时不要往那个方向走。

参考：`digest` 里的 `personas/*.md`、[抽象文化（维基）](https://zh.wikipedia.org/wiki/%E6%8A%BD%E8%B1%A1%E6%96%87%E5%8C%96)

## 八、社区是怎么写的（2026 调研）

写人设这行有专门的方法论，主要在 SillyTavern 角色卡圈子里沉淀。下面是查到的、**和我们原来做法冲突的部分**，照着改了。

### 1. 为什么角色会崩（四个机制）

| 机制 | 说明 | 我们踩过 |
|---|---|---|
| **标签自带权重** | 写「毒舌/傲娇/天然呆」，模型直接调到刻板模板 | 第一版就是标签堆的 |
| **重复 = 加权** | 同一个词出现越多，越压倒其他特质 | 「话痨」写三遍，别的都没了 |
| **细节会被循环** | 口头禅会被反复用到死 | 阿澈第一版每句都在「算」 |
| **否定 = 粉红大象** | 只写「不要油腻」，注意力反而盯着油腻 | 只写了「别做」，没写替代 |

### 2. 用「矛盾轴」代替标签

不写「他很冷静」，写：

> **你信「一切都该被计算」，可你真正怕的是被人落下。**

结构分四层：**浅层表现 → 深层底色（矛盾体）→ 性格解释 → 行为红线**。
矛盾轴的好处是：它决定角色怎么**选**，不决定他怎么**说**——所以不会念出来，但每句话都受影响。

### 3. 行为代替形容词

删掉所有形容词，换成一个能看见的动作：

- ❌ 他很冷静
- ✅ 被叫到名字，会停半秒，像在算谁在叫他

### 4. 语言指纹 + 三句测试

固定四件事：**句长 / 词汇 / 标点 / 绝不会说的话**。

然后给三句样本，**遮住名字还能认出是谁**才算过。

我们给阿澈的是：

```
投糖糖。（投她不用还人情）
你骂我。记一笔。
这波我亏了，但亏得起。
```

### 5. 红线要「否定 + 理由 + 替代」

只说"不要 X"，模型会一直想着 X。写成三段：

> 不解释自己的感受 → 一解释就变成可怜的受害者 → 用数字说：「这波我亏了」

### 6. 说话前自检（最高杠杆）

在人格末尾放一个**不超过 6 条**的 checklist。比任何形容词都管用，因为模型会照着念一遍。

```
1. 有没有在讲道理或安慰人？→ 重写
2. 有感叹号吗？→ 删
3. 超过两句？→ 掐到最后两句
```

### 7. Claude Leak Test

> 如果这句话 Claude 会说，那就是写错了。

Claude 喜欢解释、喜欢中立、喜欢总结（「希望对你有帮助」）。角色一般不会。写的时候拿这句当尺子量一遍。

### 8. 角色不是为用户服务的

要显式允许角色**难搞、无礼、沉默**——不然它会自动变回助手人格，开始帮你解决问题。
